## コンテキスト

### 背景

本テンプレートを採用する組織の中には、開発者以外の関係者（企画・ビジネスサイド等）が日常的に参照する外部のドキュメント／Wiki管理ツールへ、リポジトリ内の文書を掲載したいという要望を持つ組織が存在しうる。一方で、本テンプレートが構築する統治機構——コードレビュー、Pull Request ベースの変更管理・監査証跡、ブランチ保護に基づく承認ゲート、`task verify`、ADR 運用、差分規模上限、CODEOWNERS（AGENTS.md「7.」、development-process.md）——は、いずれも Git リポジトリを前提として組み立てられており、外部ツール上で直接編集された文書にはこれらが及ばない。

[ADR-0007](adr-0007-diagram-notation-selection.md)（図表記法の選定）は、図のソースをリポジトリで管理し、レンダリング済み画像のみを成果物として保持することを禁じる前提を置いたうえで、論理図の記法として Mermaid を採用した。本ADRは、この「ソースはリポジトリに置く」という前提を文書一般（複製された図を含む）へ拡張し、「文書・図を外部ドキュメントツールへ複製する場合に何を満たさなければならないか」という統治要件そのものを決定する。

複製先として想定される外部ドキュメントツールの一部（商用のドキュメント／Wiki SaaS など）は、文書の追加（作成）・取得・削除の API を提供する一方、更新 API を提供しない場合がある。この場合、複製の「更新」は削除＋再作成によって行うほかなく、複製物のドキュメントIDが変化する。この運用上のコストは、複製方式そのものを決定するうえで無視できない制約である。

### 前提（Assumptions）

- 文書・図の SSoT はバージョン管理下のリポジトリに置くという原則が、constitution.md「3. 基本原則」の SSoT 原則として既に存在する。
- ADR-0007 により、図のソース（テキストまたは編集可能なソースファイル）はリポジトリで管理し、レンダリング済み画像のみを成果物として保持しないという前提が確定している。
- 複製先として想定される外部ドキュメントツールが、投入した Mermaid のコードフェンス（```mermaid）を、当該ツール内部での保存・変換を経てもなお、言語指定付きコードブロックとして復元・描画するという保証は、本ADRの時点で確認されていない（後述 U-1）。

### 制約（Constraints）

- U-1（外部ドキュメントツールのドキュメント追加 API に投入した Mermaid フェンスが、当該ツール内部での保存形式変換を経てもなお、言語指定付きコードブロックとして復元・描画されるかどうか）が未検証である間、複製の自動化（CI ジョブ・スクリプトによる複製の作成・更新・ドリフト検知）を実装しないことを、本ADRの決定の前提とする（「決定（案）」参照。規範文言の正本は standards/documentation-standards.md「3.5」）。U-1 は複製アプローチ全体が成立するかどうかを左右する、最も基礎的な未検証の前提である。
- U-2（外部ドキュメントツールの一部が更新 API を提供せず、複製の更新が削除＋再作成となり、複製物のドキュメントIDが変化する）ことに起因する、パーマリンク・コメント・タグへの影響範囲は未検証である。
- U-3（外部ドキュメントツールの取得 API が返す「プレーン」表現の正規化方法。改行コード・空白・エスケープの扱い等）が未検証であるため、ハッシュ比較等によるドリフト検知は現時点で実装できない。
- 失敗した品質ゲート・統治機構を、回避目的で弱めてはならない（憲章「自己修正ループの防止」）。本ADRは SSoT 原則そのものを弱める選択肢を採らない。

## 意思決定事項

- 決定の問い: 文書・図をリポジトリ外の外部ドキュメントツールへ複製する場合、SSoT の所在をどこに置き、複製をどのような条件・要件のもとで許容するか。
- 決定の範囲（含む）: SSoT の所在の明確化。複製を許可する条件（オプトイン方式か既定複製か）。複製物に付与すべき出所（provenance）メタデータの要件。正本と複製物の乖離を検出する仕組みの要否と、現時点での実装可否。複製の自動化に関する制約（未検証事項が解消するまでの扱い）。
- 決定の範囲（含まない）: 図表記法そのものの選定（ADR-0007 の対象）。複製の自動化実装そのもの（U-1 の解消を前提とする将来の PoC、および別途起票する ADR・PR の対象）。特定の外部ドキュメントツール製品の採用可否そのもの（採用組織が自らの ADR で個別に判断する事項であり、本ADRの規範本文はベンダー中立を保つ）。
- 期限・タイムボックス: 2026-09-05
- 未解決の問い（任意）: U-1（外部ツールのドキュメント追加 API に投入した Mermaid フェンスがネイティブ描画されるか）、U-2（更新 API 不在時の削除＋再作成によるドキュメントID変化が、パーマリンク・コメント・タグに与える影響範囲）、U-3（取得 API が返す「プレーン」表現の正規化方法）は、いずれも本ADRの時点で未検証である。これらは U-1 の解消を前提条件とする将来の PoC での追跡対象とする（「結果」参照）。

## 選択肢

> 各選択肢のメリット・デメリットは客観的・一般的事実として記載し、特定案を推奨する書き方をしない。

### 選択肢 A：外部ツールを SSoT とする案（却下）

文書・図の正本を外部ドキュメントツール側に置き、リポジトリ側はコピーまたは参照のみとする案。

**メリット**

- 外部ツールの UI 上で直接編集でき、非エンジニアの読者・執筆者にとって編集の敷居が低い。
- 検索・タグ付け・コメント等、当該ツールが提供する付随機能をそのまま活用できる。

**デメリット**

- constitution.md が定める「文書・図の SSoT はバージョン管理下のリポジトリに置く」原則に正面から反する。
- コードレビューによる変更統制、Pull Request ベースの監査証跡、ブランチ保護に基づく承認ゲートが、外部ツール上の文書には及ばなくなる。本テンプレートが構築する統治機構（`task verify`、ADR 運用、差分規模上限、CODEOWNERS 等）が、文書に対しては丸ごと機能しなくなる。
- コードと文書の変更履歴が分断され、単一のコミットで両者を追跡できなくなる。

### 選択肢 B：複製せずリンクのみとする案（却下）

外部ツール側にはリポジトリ内の該当ファイルへのハイパーリンクのみを置き、本文そのものは複製しない案。

**メリット**

- 複製に伴う二重管理・乖離のリスクがそもそも発生しない。
- 実装・運用コストが最小である。

**デメリット**

- 外部ツール上にしかアクセスしない読者、またはリポジトリを横断して参照する習慣を持たない読者にとって、リンク先を開くという行為自体が行われない場合、内容は事実上到達不能になる。非エンジニアの利害関係者の多くは外部ツールしか開かない運用が想定されるため、リンクのみでは「外部ツールに掲載して読者へ届ける」という目的そのものが達成されない。
- リポジトリへの閲覧権限が外部ツールの閲覧者に付与されていない体制では、リンクをたどっても内容を閲覧できない。

### 選択肢 C：SSoT は Git、外部ツールは opt-in の派生コピー（出所ヘッダ必須）とする案（採用）

文書・図の SSoT はリポジトリに置いたまま、front matter 等で明示的にオプトインした文書に限り、出所（複製元リポジトリ・複製元パス・生成元コミットSHA・生成日時・手動編集を禁止する旨）を機械可読な形で埋め込んだ派生コピーを、外部ドキュメントツールへ置くことを許容する案。

**メリット**

- SSoT を唯一無二に保ったまま、外部ツールにしかアクセスしない読者にも内容を届けられる。
- 複製はオプトインかつ出所明示のため、どの文書が複製対象か、どのコピーがどのコミット由来かを機械的に追跡できる。

**デメリット**

- 複製先ツールが更新 API を持たず削除＋再作成のみを提供する場合、更新のたびに複製物のドキュメントIDが変わりうる（U-2）。パーマリンク・コメント・タグへの影響範囲は未検証である。
- 正本と複製物の乖離を検出する仕組みが未整備の間は、複製が更新されないまま放置され、乖離したまま気づかれない可能性が残る。
- 複製そのものの運用手順（誰が・いつ・どうやって複製するか）を新たに整備・保守するコストが発生する。

## 評価

スコアは 1（劣る）〜5（優れる）。重みは「評価観点」の値（3 / 2 / 2 / 2 / 1）。

| 評価観点（重み） | A: 外部ツールをSSoTとする案 | B: 複製せずリンクのみとする案 | C: SSoTはGit・外部ツールはopt-in派生コピー（採用案） |
|---|---|---|---|
| 監査証跡・変更管理との整合（3） | 1 | 5 | 5 |
| 読者到達性（2） | 5 | 1 | 4 |
| 運用コスト（2） | 3 | 5 | 2 |
| 乖離リスク（2） | 5 | 5 | 3 |
| 可逆性（1） | 1 | 5 | 4 |
| **加重合計（重み付け時）** | **30** | **42** | **37** |

**評価メモ**

> 加重合計だけを見ると B（42）が C（37）を上回るが、これは「読者到達性」を他の観点と同列の連続的なトレードオフ対象として扱った結果に過ぎない点に留意されたい。読者到達性は本来、外部ツールへ掲載する目的そのものを規定する閾値的（ゲーティング）要件であり——ほぼ到達しないという結果は、他の観点でどれだけ優れていても外部公開の目的自体を無効化する——単純な重み付き線形和で他の観点と相殺してよい性質のものではない。したがって加重合計の最大をもって機械的に決定はせず（adr-template.md「評価」節の規約どおり）、B は「デメリット」に記載した到達性の欠陥を理由に不採用とする。A は加重合計でも最下位（30）であり、かつ最も重み（3）の大きい観点で最低評価（1）となっている。これは統治機構が丸ごと及ばなくなるという構造的な欠陥であり、他の観点の優劣で相殺できる性質のトレードオフではない。

## 決定（案）

起案者およびレビューアが記入する。本セクションは承認前の決定案であり、決定の確定は次セクション「承認」による。

- 採用する選択肢（案）: 起案者の提案は選択肢 C（SSoT は Git、外部ツールは opt-in の派生コピー）である。人間承認により決定（案）から決定に確定する。
- 決定理由: SSoT をリポジトリ内に唯一無二に保つことで、本テンプレートが構築する統治機構（コードレビュー・監査証跡・承認ゲート）を文書に対しても維持できる。同時に、複製をオプトインかつ出所明示で許容することで、外部ツールにしかアクセスしない読者にも内容を届けるという実務上の要請にも応える。加重合計では B が上回るが、「評価メモ」に記載のとおり読者到達性はゲーティング要件として扱い、単純な線形和での比較にはなじまないと判断した。
- 不採用案を選ばなかった理由: A は監査証跡・変更管理という最も重み付けの高い観点で構造的に破綻し、本テンプレートの統治機構全体が文書に対して機能しなくなる。B は複製に伴うコスト・リスクを一切負わないが、外部ツールにしかアクセスしない読者に内容が実質的に到達しないため、外部ツールへ掲載する目的そのものを達成できない。
- 前提条件・制約: 複製対象文書は front matter で明示的にオプトインした場合に限り複製対象とし、既定は複製しないことを前提とする。複製物には出所（複製元リポジトリ・パス・コミットSHA・生成日時・手動編集禁止の明記）を機械可読な形で含めることを前提とする。正本と複製物の乖離を検出する仕組みは現時点で未整備であり、その実装は U-1〜U-3 の解消後に検討する。複製の自動化（CI ジョブ・スクリプトによる複製の作成・更新・ドリフト検知）は、U-1（外部ツールが Mermaid フェンスをネイティブ描画するか）が未検証である間は行わないことを、決定の前提条件とする。これらの規範としての MUST／MUST NOT の文言の正本は standards/documentation-standards.md であり、本ADRでは再掲しない。それまでの複製手順は playbooks/external-doc-replication.md に記す手動手順のみとする。
