# GP-0003: 強制台帳のスキーマ拡張と機械検証

> ガバナンス決定（憲章「7. 変更管理」）。統治改訂プロンプト（Machine-First Verification 導入）WU-02。
> WU-01（[GP-0002](gp-0002-machine-first-verification.md)。PR #22、`refactor/framework-neutral-ui-governance` へマージ済み）に依存する。

## 1. 提案の要旨

WU-01 は憲章「1.1」の強制手段分類を「人間ゲート（不可避）／人間ゲート（暫定）」に改称したが、`governance/enforcement-ledger.md` 側は旧称のまま据え置いた（同 PR の改正履歴に「依存後続の作業単位で実施する」と明記）。本提案はその一括移行を行い、あわせて新分類が要求する必須項目（理由区分・失効期限・担当・移行先ゲート）を機械検証する。

## 2. 変更内容

## 3. WU-02 のタスク定義との対応、および実装上の判断

プロンプトの WU-02 は4つのチェックを列挙し、「上記4を task verify に配線し、違反時に非ゼロ終了させなければならない（MUST）」と定めている。うち3つ（人間ゲート（不可避）の理由区分非空／人間ゲート（暫定）の必須項目非空／失効期限超過ゼロ）は台帳という**私が完全に構造を制御する表**に対する検査であり、正規表現で確定的・機械的に判定できるため、そのまま非ゼロ終了（hard fail）として実装した。

残る1つ（「constitution.md の全 MUST/MUST NOT が台帳に行を持つ」＝網羅性検査）は、**正確な実装が技術的に困難**であるため、advisory（非ブロッキング・WARN 相当）として実装した。理由:

* 憲章本文中の「（MUST）」「（MUST NOT）」は自由文中の記述であり、1つの台帳行が複数の MUST を束ねる場合（例: #23「MUST / MUST NOT」）や、逆に1つの MUST が複数行に分解される場合があり、出現数と行数の単純な数値一致を機械的に要求すると、正当な変更で恒常的に失敗する偽陽性ゲートになる。
* これは本台帳自身が過去に経験した失敗パターン（改正履歴 [0.3.0] の #29 新設理由: lychee の偽陽性・adoption.sh の CI 無効化・ui:tokens:check の誤合格）と同種のリスクである。「整備済み」と主張しながら実際には機能しない、または過検知で信頼を失うゲートを作ることは、本改訂全体の目的（機械検証の質を上げる）に反する。
* したがって、出現数の粗い突合を**助言として出力**し、真の網羅性確認は憲章「7. 変更管理」定期見直し（6ヶ月ごと）に委ねる設計とした。台帳の該当行（#35）の整備状況は「整備中」とし、「整備済み」と過大に主張しない（憲章「8. ブートストラップ規定」の趣旨）。

**この設計判断（advisory化）はプロンプトの文言「違反時に非ゼロ終了させなければならない」を字義通りには満たさない。人間による承認・修正の対象として明示する**（下記「5. 未解決事項」Q-03）。

## 4. 影響範囲

| 観点 | 影響 |
| --- | --- |
| 既存の義務 | **撤廃・反転なし**。呼称の統一と、明白な誤記（整備状況列への「ブートストラップ」混入）の是正が中心 |
| 既存30行の再分類結果（重要な発見） | (a)/(b)/(c) の判定基準を既存の全「人間」関与行に厳密に適用した結果、**人間ゲート（暫定）に該当する行は0件**となった。既存の「ブートストラップ」表記の大半は「機械化待ちの一時措置」ではなく「原理的に自動化困難な恒久的人間判断（意味的判断・責任の引受）」であったことを示す。これは統治の実態に関する具体的な知見であり、本 WU の当初の想定（人間ゲート（暫定）が一定数生まれ、機械化ロードマップの起点になる）と異なる結果である |
| `task verify:fast` | 新規チェック（`enforcement-ledger`）が追加される。現状は違反0件のため通過する |
| コードを含まない採用 | 影響なし（台帳・スクリプトはコードスタック非依存で動作） |
| AI エージェントの権限 | 変更なし |

## 5. バージョン増分の判定

**governance/enforcement-ledger.md: 0.4.0 → 0.5.0（提案・MINOR）**。新規列・新規行の追加が中心で、既存規範の意味を反転させる変更はない。列の誤用是正（#4等の整備状況表記）は「記録の正確化」であり規範そのものの変更ではないが、可読性・監査性への実質的な影響があるため PATCH ではなく MINOR とした。**constitution.md は本提案の対象外（無変更）**。
