# GP-0002: 検証手段の選択原則（Machine-First Verification）の新設

> ガバナンス決定（憲章「7. 変更管理」）。統治改訂プロンプト（Machine-First Verification 導入）WU-01 の成果物。

## 1. 提案の要旨

「生成AIの実装は誤りうる。ゆえに人間が確認しなければならない」を無条件の終着点とせず、**人間ゲートを選択してよい条件を明示し、条件に合わないものを機械強制への移行対象として追跡可能にする**。

現行の憲章「1.1 義務レベルと強制手段」は「機械強制」「人間ゲート」「構造的強制」「未整備（ブートストラップ）」の4分類を既に持ち、「MUST/MUST NOTは可能な限り機械強制を優先する」も既に明文化されている。しかし、**人間ゲートを選んでよい条件そのものが未定義**であり、条件が無いため「この人間ゲートは外してよいか」を判断する基準もない。本提案はこの欠落を埋める。

## 2. 変更内容

### 2.1 憲章（constitution.md）— Class A

| 対象 | 変更 |
| --- | --- |
| 「3. 基本原則」 | 新設「検証手段の選択（Machine-First Verification）」。強制手段の選択順位（構造的強制 → 機械強制 → 人間ゲート）を MUST 化。人間ゲートの正当な目的を (a) 意味的判断／(b) 責任の引受／(c) 法令・契約・規制要求 の3区分に限定（MUST NOT：理解確保目的での設置）。非該当の人間ゲートは失効期限付きで強制台帳へ登録（MUST）。 |
| 「1.1 義務レベルと強制手段」 | 強制手段分類表を改称: 「人間ゲート」→「人間ゲート（不可避）」、「未整備（ブートストラップ）」→「人間ゲート（暫定）」。運用原則の箇条書きを新称・新原則と整合させた。表の見出し文言の誤り（「3種類」）を実態（4種類）へ修正。 |
| 「6. AIエージェント統治と自律境界」承認マトリクス | 「理由区分」列を追加し、全12行に (a)/(b)/(c) を記入。 |

| バージョン | 0.3.0 → **0.4.0（提案。MINOR）**。根拠は本提案「4. バージョン増分の判定」。 |

### 2.2 強制台帳（governance/enforcement-ledger.md）— Class A

新設した3つの MUST / MUST NOT を #31〜#33 として登録した（現行スキーマのまま。理由区分列・失効期限列は未追加）。いずれも現時点は「未整備」（人間レビューで暫定担保）。

台帳の凡例・既存 #1〜#30 の「強制手段」列は、憲章 1.1 の新称（人間ゲート（不可避）／（暫定））へまだ追従していない。これは意図的な**未実施**であり、次の作業単位（WU-02: 強制台帳のスキーマ拡張と機械検証）で一括対応する。

## 4. バージョン増分の判定

**提案: MINOR（0.3.0 → 0.4.0）**

根拠:

* 既存の MUST / MUST NOT の**撤廃・反転・意味変更はない**。「人間ゲート」呼称の分割（不可避／暫定）は、既存の各行が現に担っている拘束を変更せず、既存カテゴリの内部区分を明確化する追加的分類にとどまる。
* 新設した3つの MUST / MUST NOT（強制手段の選択順位・人間ゲートの目的限定・非該当ゲートの台帳登録義務）は、既存ルールに対する**後方互換な追加拘束**であり、既存の義務を弱めない。
* 憲章「7. 変更管理」バージョニング方針の MINOR 例示「新しい原則の追加、第8章への MUST ルール追加」に該当する（本件は3章への追加だが、性質は同じ「新規MUST追加」である）。
* MAJOR の例示（承認マトリクスの要件削除、原則の規範的意味の変更、Class定義の再定義）には該当しない。要件を**削除**してはおらず、**追加**している。

現行は `0.y.z`（Status: Proposed の未批准期間）であり、この期間の規範は後方互換性を保証しない（憲章冒頭）。したがって形式上は MINOR/MAJOR いずれの判定でも許容されるが、実質が追加的拡張である以上、**MINOR 系列を維持することが実態に即している**と判断する。

**この判定はAIによる提案であり、確定（Accepted 化）は人間承認者が行う**（憲章「7.」：AI は本書改正を単独で承認・反映してはならない MUST NOT）。
