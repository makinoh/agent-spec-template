# GP-0007: UI 領域に閉じ込められた汎用原則の昇格

> ガバナンス決定（憲章「7. 変更管理」）。統治改訂プロンプト WU-06 の成果物。

## 0. 影響の要旨（最重要・最初にお読みください）

**本提案は、UI を持たない既存採用に対して新たな MUST を課します（WU06-02 / NG-06 開示義務）。**

憲章「10.1 UI 再現性」は「UI を持たない採用では休眠する」と定義されています（`package.json` と `src/` の追加で活性化）。しかし 10.1.3 / 10.1.5 / 10.1.7 の中に含まれる3つの規定は、実質的に UI 固有ではありませんでした。これらは休眠する 10.1 の内側に閉じ込められていたため、**UI を持たない採用ではこれらの規定そのものに到達しません**。これは意図的な制限ではなく設計上の欠落です。

本提案は、この3規定の一般原則部分を憲章「3. 基本原則」および「6. AIエージェント統治と自律境界」へ昇格します。昇格の結果、**UI を持たない既存採用にも、以後は次の MUST / MUST NOT が新たに適用されます**（従来は「10.1」全体が休眠していたため到達しなかった規範に、以後は到達します）。

| 昇格後の原則 | 新たに適用される義務（要約） | UI を持たない採用への影響 |
| --- | --- | --- |
| 「3. 基本原則」仕様と検証装置の分離 | 検証装置（テスト・チェックスクリプト等）を仕様と同一視してはならない（MUST NOT）。検証装置は仕様から導出される（MUST） | 新規適用（従来は UI 領域のみ） |
| 「3. 基本原則」検証は実行可能でなければならない | 自己申告のみを完了の成果として認めない（MUST NOT）。Class A／B の完了報告に実行コマンドと生の出力を含める（MUST。**適用範囲は本提案「5. 未解決事項」で未確定**） | 新規適用（従来は UI 領域のみ） |
| 「6.」HITL 停止必須チェックポイント：推測の禁止 | 仕様に記載のない値・構造・文言を発明しない（MUST NOT）。`[NEEDS CLARIFICATION]`／Open Questions 未解決時は実装に着手せず停止する（MUST） | 新規適用（従来は UI 領域のみ） |

これは義務の**削減ではなく拡大**です。既存の UI 固有規定を撤回・弱体化するものではなく、UI 採用側には実質的な変更はありません（10.1.3/10.1.5/10.1.7 は UI 固有の具体化のみを残す残置規定として存続します）。

## 1. 提案の要旨

「10.1 UI 再現性」は UI を持たない採用では休眠すると憲章冒頭で定義されています。しかし 10.1.3（推測の禁止）・10.1.5（検証は実行可能でなければならない）・10.1.7（UI 文書の役割分担）の3規定は、内容の本体が UI 固有ではありません。

* 10.1.3「記載のない値・構造・文言の発明禁止」「一般的には、による補完の禁止」は、あらゆる仕様駆動開発に適用可能な HITL（Human-in-the-Loop）停止原則である。
* 10.1.5「自己申告を成果と認めない」「完了報告に実行コマンドと生の出力を含める」は、UI に限らずあらゆる完了報告に適用可能な Machine-First Verification の帰結である。
* 10.1.7「検証装置（Storybook）を仕様と同一視しない」は、検証装置一般（テスト・Lint・チェックスクリプト等）に適用可能な自己言及防止原則である。

これらが UI 領域にのみ閉じ込められていることで、UI を持たない採用（本リポジトリの多くの想定採用先を含む）はこれらの規範に到達できません。本提案はこの欠落を埋めます。

なお、10.1.3 は既にその末尾に「本項は『6. AIエージェント統治と自律境界』の停止必須チェックポイントを UI 領域へ具体化したものです」という一文を持っていました。これは元の起草者が一般原則の存在を意図していたが、実際には6章側に対応する内容が無く、参照が事実上宙に浮いていたことを示します。本提案はこの参照を実体化します。

## 4. バージョン増分の判定

**提案: MINOR（0.4.0 → 0.5.0）**

根拠:

* 既存の MUST / MUST NOT の**撤廃・反転・意味変更はない**。10.1.3/10.1.5/10.1.7 が既に保持していた規範を、より広い適用範囲（UI を持たない採用を含む）へ再配置するものであり、UI 領域における実際の義務内容は変わらない。
* 新たに一般原則として昇格した MUST / MUST NOT（仕様と検証装置の分離、検証は実行可能でなければならない、推測の禁止）は、UI を持たない採用にとっては形式上「新規」だが、既存原則（3章の他原則、6章の HITL 停止原則群）に対する**後方互換な追加拘束**であり、既存の義務を弱めない。
* 憲章「7. 変更管理」バージョニング方針の MINOR 例示「新しい原則の追加、第8章への MUST ルール追加」に該当する。
* MAJOR の例示（承認マトリクスの要件削除、原則の規範的意味の変更、Class定義の再定義）には該当しない。**要件を削除しておらず、適用範囲を拡大**している。

ただし、UI を持たない採用にとって新規 MUST が生じる点は、通常の MINOR（「機能追加」的な拡張）よりも実務上のインパクトが大きい可能性がある。この点も含め、増分種別の最終判定は人間に委ねる。

現行は `0.y.z`（Status: Proposed の未批准期間）であり、この期間の規範は後方互換性を保証しない（憲章冒頭）。**この判定はAIによる提案であり、確定（Accepted 化）は人間承認者が行う**（憲章「7.」：AI は本書改正を単独で承認・反映してはならない MUST NOT）。**この判定は提案であり、確定は人間に委ねる**。
