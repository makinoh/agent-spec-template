# Playbook: 外部ドキュメントツールへの複製（手動）

* 変更クラス: C（`playbooks/**`。development-process.md「1.」）
* 上位規範: [standards/documentation-standards.md](../standards/documentation-standards.md)「3.」／
  [ADR-0008](../adr/adr-0008-external-doc-tool-replication.md)

> **本手順は手動専用です。** 複製の作成・更新・乖離検知を行う CI ジョブやスクリプトは、本書の対象時点では一切導入しません。自動化は、外部ドキュメントツールの文書追加APIが、投入した Mermaid コードフェンス（```mermaid）を言語指定付きコードブロックとして復元・描画するかという前提（未検証。standards/documentation-standards.md「4. 付録」）が解消された後の、将来のPoC（概念実証）に委ねます（同「3.5」）。本書はそれまでの間、人間が手で行う手順のみを定めます。

---

## 目的

一部の関係者（非開発者を含む）は、Git リポジトリではなく外部のドキュメント／Wiki管理ツール上で文書を参照する運用に慣れています。本Playbookは、そうした読者に届けるために文書を外部ドキュメントツールへ複製する場合の、具体的な手動手順を定めます。

複製はあくまで**リポジトリ内容の派生コピー**であり、複製先を正本として扱ってはなりません（MUST NOT。standards/documentation-standards.md「1.」「3.」）。本Playbookの目的は、正本をリポジトリに保ったまま、複製という運用上の便宜を安全に行うための具体的な手続きを与えることです。複製そのものを行うかどうか、複製先に何を選ぶかは各採用組織の判断であり、本Playbookはその判断を前提とした後工程のみを扱います。

---

## 前提

- 本手順は、standards/documentation-standards.md「3.1」に基づき front matter で複製対象と明示された文書にのみ適用します。オプトインしていない文書を複製してはなりません（MUST NOT）。
- 本手順は、次の未検証の前提の上に成り立っています（詳細は standards/documentation-standards.md「4. 付録」）。これらが崩れた場合、本手順そのものの有効性は保証されません。
  - 外部ドキュメントツールの文書追加APIが、投入した Mermaid コードフェンスを言語指定付きコードブロックとして復元・描画するかどうか（**最重要・未検証**。複製アプローチ全体の成否を左右する）。
  - 当該ツールが文書の更新APIを持たず、「更新」が削除・再作成としてしか行えない場合、documentId の変化がパーマリンク・コメント・タグに与える影響範囲（未検証）。
  - 当該ツールの取得APIが返す「プレーンテキスト」表現の正規化方法（改行コード・空白・エスケープの扱い等。未検証。ハッシュベースのドリフト検知に必要）。
- 上記が未検証である間、本手順は前提の妥当性を**都度・手作業で確認しながら**進める運用とし、確認を省略してはなりません（MUST NOT。詳細は「複製手順」参照）。
- 恒久的に安定したURLを維持する必要があるエントリーポイント文書（例: トップページ・目次ページ）は、自動再生成の対象から除外するべきです（SHOULD。standards/documentation-standards.md「3.4」）。本手順の「更新手順（削除・再作成）」は複製物のIDを変化させるため、対象文書がこれに該当するかどうかは削除の**前**に必ず確認してください。
- 採用組織が複製先として具体的にどのツールを用いるかは、自組織のADRで個別に選定してください。特定ツールの記法対応状況に関する参考情報（非規範）は standards/documentation-standards.md「4. 付録」を参照してください。

## 複製対象の選定（front matter による opt-in）

本書の新設時点で、複製対象のオプトインを表す front matter の形式はリポジトリ内のどのスキーマにも未定義です。本Playbookは、次の形式を**新規の規約として**導入します。

```yaml
---
external_doc_replication: true
external_doc_id: null   # 複製後に払い出された外部文書IDを人手で記入する。複製前は未設定でよい
---
```

- `external_doc_replication: true` を front matter に持つ文書のみを複製対象としなければなりません（MUST）。このキーを持たない文書、または値が `true` 以外の文書を複製してはなりません（MUST NOT。standards/documentation-standards.md「3.1」）。既定（何も指定しない場合）は複製しないことです。
- `external_doc_id` は、複製後に外部ツールから払い出される文書IDを追記するための欄です。複製前は存在しなくても構いません（任意）。文書本体の front matter に外部IDを持たせたくない場合、または一つの文書を複数の外部ツールへ複製する場合は、front matter の代わりにリポジトリ内のマッピング表（採用組織が用意する）に記録してもよい（MAY）。
- 上記2キーは本Playbookが新設する規約であり、本書の新設時点で他の文書テンプレート（front matter スキーマ）には存在しません。既存文書への追加自体の変更クラスは、対象文書のパス区分（development-process.md「1.」対象パス表。複数該当時は最も厳格なクラスを採用）に従います。対象が統治・強制機構に該当する文書（constitution / governance / standards / AGENTS.md 等）であれば Class A として扱ってください。

## 複製前に埋め込む出所ヘッダの様式

複製物の内容には、複製先へ投入する**前**に、次のテンプレートを先頭へ人手で貼り付け、プレースホルダを実際の値に置き換えます。この来歴メタデータは機械可読な形式（HTMLコメント内のキー・値）で保持し、あわせて人間向けの編集禁止の明記を添えます（standards/documentation-standards.md「3.2」）。

```text
<!--
external-doc-provenance:
  source_repository: "https://github.com/<org>/<repo>"
  source_path: "<リポジトリ内の相対パス、例: standards/documentation-standards.md>"
  source_commit: "<生成元コミットのフルSHA>"
  generated_at: "<ISO 8601 UTC、例: 2026-09-05T12:00:00Z>"
  notice: "このコピーは自動生成物であり、直接編集しないこと。編集は出所リポジトリで行い、再生成すること。"
-->

> **このページは自動生成された複製物です。直接編集しないでください。**
> 編集は出所リポジトリの該当ファイルで行い、本複製を再生成してください（出所は上記コメントを参照）。
```

- `source_commit` には、複製作業を行う時点でその文書が最後に変更されたコミットのフルSHAを用います。
- `generated_at` には、複製（または再生成）を実行した日時を ISO 8601（UTC）で記入します。
- このヘッダを欠いたまま文書を複製先へ投入してはなりません（MUST NOT）。

## 複製手順（手動）

1. **複製対象の特定**: front matter に `external_doc_replication: true` を持つ文書を確認します。このキーを持たない文書を複製してはなりません（MUST NOT。「複製対象の選定」参照）。
2. **出所ヘッダの埋め込み**: 複製元文書の内容をコピーし、その先頭に前節のテンプレートを貼り付け、プレースホルダを実際の値（出所リポジトリURL・ソースパス・commit SHA・生成日時）に置き換えます。
3. **外部ドキュメントツールへの投入**: 出所ヘッダを付与した本文を、外部ドキュメントツールの文書追加（作成）操作を用いて**新規文書として**投入します。既存の複製物がある場合でも、上書き・更新の操作ではなく新規作成として扱います（更新APIが存在しない前提。「前提」参照）。
4. **外部文書IDの記録**: 投入後にツールから払い出される文書ID（documentId等）を、複製元文書の front matter（`external_doc_id`）またはリポジトリ内のマッピング表に追記し、以後どの外部文書がどの複製元に対応するかを追跡できるようにします（standards/documentation-standards.md「3.2」の来歴と対にする）。
5. **Mermaidレンダリングのスポットチェック**: 投入した文書を実際に開き、本文中の Mermaid コードフェンスが図として正しくレンダリングされていることを目視で確認します。**これは「前提」に挙げた最重要の未検証事項（文書追加APIが Mermaid フェンスを復元・描画するか）を、都度・手作業で検証していることに他なりません。** 当該前提が正式に検証・解消されるまでの間、複製のたびにこのスポットチェックを省略してはなりません（MUST NOT）。レンダリングされていない場合は、外部ツールへの投入を完了として扱わず、原因を確認したうえでやり直します。

### 更新手順（削除・再作成）

複製先の外部ドキュメントツールが更新APIを持たない場合、既存の複製物を更新する手段は削除・再作成のみです。

0. **削除してよいか先に確認**: 対象文書が、恒久的に安定したURLを要するエントリーポイント文書（トップページ・目次ページ等。standards/documentation-standards.md「3.4」）に該当するかを確認します。該当する場合は本削除・再作成の手順を適用せず、文書オーナー（「乖離が見つかった場合のエスカレーション先」参照）に判断を仰いでください。
1. 既存の外部文書を削除します。
2. 上記「複製手順」の 2〜5 を改めて実行し、更新後の内容を新規文書として再作成します。
3. **再作成によって外部文書のIDが変わることを認識してください。** 旧IDを前提にしたパーマリンク・コメント・タグ等の参照は、再作成後に壊れる可能性があります（影響範囲は未検証。「前提」参照）。作業前に、旧IDへの既知の参照（他文書からのリンク、関係者が個別に保存したブックマーク等）がないか確認し、見つかった場合は当該参照の持ち主に個別に周知します。
4. 「外部文書IDの記録」で記録した ID を、新しく払い出された ID に更新します。

## 乖離が見つかった場合のエスカレーション先

正本（リポジトリ内の文書）と複製物との間の内容の乖離（ドリフト）を機械的に検知する仕組みは、本書の新設時点で未整備です（standards/documentation-standards.md「3.3」。対応する行は governance/enforcement-ledger.md に本書の新設時点では未登録です）。したがって、乖離の発見は当面、人間が気づくことに依存します。

- ソース文書が更新されたのに複製物が再生成されていない、または複製物が独自に手編集されて出所ヘッダの内容と矛盾している、といった乖離に人間が気づいた場合は、[governance/risk-register/](../governance/risk-register/README.md) へ記録するか、当該文書のオーナーへ報告します。
- 文書オーナーの具体的な役割・担当者名は、本テンプレートでは確定しません。採用組織が確定してください（`TBD-HUMAN`。development-process.md と同様の趣旨）。
- 乖離への対応（複製物を再生成する／複製を停止する等）そのものの判断は、上記のエスカレーション先が行います。本Playbookは検知後の対応手順までは規定しません。

## 確認

- [ ] 複製元文書の front matter に `external_doc_replication: true` があることを確認した
- [ ] 出所ヘッダ（出所リポジトリ・ソースパス・commit SHA・生成日時・編集禁止の明記）を本文先頭に埋め込んだ
- [ ] 外部ドキュメントツールへは新規作成として投入した（既存複製物の上書き・更新ではない）
- [ ] 投入後の文書を開き、Mermaid コードフェンスが図としてレンダリングされていることを目視確認した
- [ ] 払い出された外部文書IDを front matter またはマッピング表に記録した
- [ ] （更新の場合）対象文書が安定URLを要するエントリーポイント文書に該当しないことを確認した（該当する場合は削除・再作成を行わず文書オーナーへ判断を仰いだ）
- [ ] （更新の場合）削除・再作成によって外部文書IDが変わることを踏まえ、既知の参照（リンク・コメント・タグ）への影響を確認した
